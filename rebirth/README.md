# 링구 RPG Rebirth — 구현 작업

## 2026-09-21 이어서 작업한 내용

- 이미지 24개를 WebP로 변환하고 게임 참조를 변경: 58,357,408 → 9,988,472바이트(82.9% 감소). 원본 PNG는 유지. GitHub 앱의 텍스트 파일 업로드에 맞춰 WebP를 내장한 SVG로 게임에 연결하고, 한글 글꼴도 CSS에 내장.
- 연결 실패 시 자동 재시도를 5초부터 최대 60초까지 늦춰 반복 요청을 줄임.
- 직업을 바꿀 때 입력한 캐릭터 이름 유지.
- Edge Function 외부 호출에 10초 제한 추가. ringu-rebirth v3 배포 완료.
- 사용자 지시대로 이번 작업에서는 테스트·시뮬레이션·브라우저 검증을 실행하지 않음.
- 새게임 공개 스위치는 false이며 계정 초기화·운영 페이지 전환은 아직 실행하지 않음.
- 아래 초기 작업 기록은 과거 상태다. 이미지·보관함·도감·던전 전투는 이후 코드에서 구현됐으며, 파티 콘텐츠와 최종 운영 전환은 남아 있다.


사용자 최종 지시: 모든 기존 계정·진행 데이터 초기화, 모바일 우선/PC 대응, 오프라인 최대 6시간, 2~4개월 이상 성장, 직업 5개, 레벨제 드롭 장비, 25성, 잠재 1~3줄과 큐브.

운영 저장소: dkdrlahWl/linsa-rpg. cloud-config.js의 Supabase ref: ekgihnyojihpearcudtd. 기존 서비스와 일치 확인 완료. lingooo-RPG는 다른 서버를 참조하는 과거 저장소이므로 수정 대상이 아니다.

계정 삭제는 새 런타임, 서버, 백업, 복구 절차가 준비된 이후 실행한다. 삭제 권한은 사용자에게 이미 받았으며 같은 허가를 반복 요청하지 않는다. 현재는 아무 계정도 삭제하지 않았다.

시안 이미지는 비주얼 참고이며 화면 숫자는 밸런스의 근거가 아니다. 현재 낙관적 시뮬레이션은 장비 즉시 확보 가정에서 1일 12시간 정산 시 200레벨 약 92일이다. 실제 보스·파밍 지연을 포함한 중앙 성장 시간은 아직 검증되지 않았다. 최대 강화·잠재는 120일 이후에도 남는 목표로 둔다.

완료하지 않은 기능, 자산, 서버 연결을 완료로 보고하지 않는다. 구버전 서비스는 전환 시점까지 보존한다.

## 초기 작업 기록 — 이후 변경 전 상태

- 새 계산 모듈: 5직업, 경험치, 6시간 상한, 레벨제 장비, 25성, 잠재, 큐브, 제작, 기본 보스 로직 작성.
- UI 초안: 사냥/지역/캐릭터/장비/보스/거래 탭, CSS 이펙트, 합성 효과음 및 반복음 작성. 아직 실제 브라우저 렌더 검증 전.
- DB: `rebirth_isolated_foundation` 적용. `rebirth_private.release.enabled=false` 유지.
- Edge Function: `ringu-rebirth` v1 배포, JWT 검증 켬. 실제 유저의 개편 게임 사용은 release에서 차단.
- 운영 `index.html`, 기존 계정과 구버전 서버는 수정하지 않음.
- 로컬 테스트: `node rebirth/engine.test.mjs`, `node rebirth/db.test.mjs` 통과. PGlite 테스트이며 실제 서비스 통합검증 아님.
- `node rebirth/simulate.mjs`: 낙관적 성장 하한을 계산. 확률형 장비 획득·강화 비용까지 포함한 플레이어 시뮬레이션은 남아 있음.
- 브라우저 검증: Playwright 기본 바이너리 다운로드 시간 초과. 대체 Chromium 153 바이너리도 `--version`부터 SIGSEGV로 종료하여 렌더 확인 불가. 브라우저 테스트를 통과한 것으로 보고하면 안 됨.
- 신규 직업 이미지 5종 포함. 기존 보스/장비 아트를 임시 연결한 부분이 있으며, 새 지역/일반 몬스터/직업별 무기/장비 단계별 외형 완성은 남아 있음. 생성한 30종 보스 atlas는 규칙적 셀 배치에 실패해 게임에 적용하지 않음.

## 반드시 완료할 남은 작업

1. 일반 몬스터 60종/지역별 배경/장비 및 직업별 시각 자산, 직업 스킬 차별화, 장비 비교, 도감·보관함, 파티 콘텐츠.
2. 단순 보상 지급인 던전을 실제 전투 콘텐츠로 교체하고 보스 패턴·예고·포기·재접속 처리를 완성.
3. 생성 캐릭터의 초기 무기 장착, 실제 수급 기반 강화/큐브 장기 시뮬레이션, 전체 단계 진행 가능성.
4. 타격 시각 효과와 실제 서버 결과 연결, 모바일 모달·뒤로가기·음소거·복귀 검증. 캐릭터 atlas의 표시 비율 조정.
5. 서버 상급 큐브 등급 상승 이벤트 판정 수정, 자정 경계의 보스 보상 날짜 고정, 거래 중 사냥 정산 일관성 및 판매자/구매자 잠금 순서 재검토.
6. 재접속 시 계정별 미완료 요청 복구와 market/engine 요청 충돌 처리 검증. 가방 초과 자동 분해 정책은 보관함 방식으로 변경.
7. 실제 Auth/Edge/DB 통합 검증과 모바일/PC 브라우저 검증.
8. 전체 계정 삭제 대상·세션·Storage·구버전 함수와 cron 조사, 유효 백업, 복구 계획, 새 버전 공개 후 구버전 종료 및 초기화.

운영 조회 시점 계정 23개, 진행 계정 23개, 경제 계정 23개, 활성 매물 23개. 수치는 전환 직전에 다시 확인한다. DB 약 350 MB. 전체 테이블 무차별 복사는 무료 용량을 초과할 수 있으므로 백업은 별도 저장소 또는 현행 상태 중심으로 설계한다.
