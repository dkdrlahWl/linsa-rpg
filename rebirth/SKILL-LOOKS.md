# 스킬 외형 상점

6직업별 3종, 총 18종. 각 20,000,000골드. 구매하면 영구 보유하고 해당 직업에서 장착·해제한다. 직업별 장착 선택은 각각 저장된다. 공격력 보너스가 없는 외형 전용 상품이다.

내장 image_gen으로 테마마다 투명 배경 4×5 시트를 제작했다. 각 행은 1~5차이며 네 칸에는 해당 원본 스킬의 무기·투사체·타격·잔광 요소를 담는다. 총 90개 스킬 디자인, 360개 요소. `skill-look-designs.mjs`가 테마별 이미지 버전을 선택하며 필요한 장착 테마만 전투 전에 불러온다.

6종의 v3 그림은 기본 스킬과 구별되는 실루엣을 갖는다. 비취 공작은 푸른 눈무늬 깃, 별사슴은 은빛 가지뿔, 자월 가면은 가면과 쌍초승달 칼날, 여명 세라핌은 분홍 여명의 여섯 날개, 은하수는 나선 성운, 진주 바다는 조개·진주·붉은 산호다. 1~5차의 120개 이미지 요소와 상점 대표 그림을 함께 교체했다. 기존 상품 ID·가격·소유·장착·보유 효과는 유지하며, 나머지 12종의 그림은 그대로다. 상점·전투·아레나는 같은 버전 선택 함수를 사용한다.

`skill-look-material.mjs`는 원본 렌더러가 그리는 이미지의 원본 영역만 교체한다. 목적지 좌표·크기·회전·궤적·범위 클리핑·타이밍·개수는 원본 그대로다. 전사의 검과 검기, 마법사의 마력창·운석·마법진, 궁수의 화살·저격·화살비·천궁, 도적의 칼날·분신, 해적의 탄환·포격·탄환 폭풍, 사제의 심판·치유·결계·대천사를 유지한다. 원본의 절차적 검기와 궤도는 같은 형태에 테마 색만 입힌다. 전투에서 범용 테마 그림을 크게 띄우던 대체 분기는 제거했다. 기존 차수별 투명도 설정을 따른다.

표시 크기는 투명한 셀 전체가 아닌 실제 그림의 알파 경계를 기준으로 맞춘다. 18종 360개 요소의 경계를 `scripts/build-skill-look-bounds.py`로 미리 측정해 `skill-look-bounds-data.mjs`에 저장한다. 스킬의 원래 목적지 사각형·중심·클리핑은 바꾸지 않으므로 판정 범위나 공격 궤적이 달라지지 않는다. 전투 중 픽셀 읽기는 하지 않는다. 그림 버전을 변경할 때 경계 데이터도 다시 생성해야 하며, 파일 버전이나 크기가 맞지 않으면 안전하게 셀 좌표로 돌아간다. 아레나는 그림 비율을 유지하면서 여백을 제외해 표시한다.

비취 공작과 별사슴의 5차 활은 원본 그림의 옆 방향과 기울기를 보정해 벚꽃 활처럼 아래쪽을 향한다. `skill-look-orientation.mjs`가 해당 두 활 요소만 로드 시 한 번 정렬하고 회전 여백을 제외한 결과를 재사용한다. 상점 대표 그림은 유지하며 실제 전투·일반 사냥 시전·움직이는 미리보기에서 적용된다. 다른 차수·화살·타격 요소와 월드 좌표·크기·회전·낙하 궤적은 유지한다.

실제 5차의 큰 활은 `fifth-effects.mjs`의 무기 그리기 지점에서 `skill-look-source.mjs`를 통해 장착 테마의 정렬된 그림을 직접 받는다. 임시 원본 캔버스의 WeakMap 등록 여부에 의존하지 않으며 모듈 복사본 사이에서도 같은 Symbol 키를 사용한다. 원래 표시 사각형과 시전·화살 낙하 진행은 그대로 사용한다. 이 경로를 바꿀 때 미리보기 외에 게임과 같은 import map을 적용한 실제 TowerRenderer 보스 전투도 검사한다.

사제 세 외형은 기본 시트의 3:4 사각형에 인물 그림을 강제로 맞추지 않는다. `skill-look-fit.mjs`에서 같은 배율로 가로세로를 확대해 얼굴·몸·날개 비율을 유지한다. 기존 시각 높이와 수평 중심은 유지하며 그림의 폭만 자연 비율에 맞춘다. 이 인물 그림의 폭 보정은 위의 원본 목적지 유지 규칙에 대한 사제 전용 예외다. 바닥의 범위 표시·효과 위치·클리핑·피해·회복 판정은 유지하고 다른 직업의 표시 크기는 변경하지 않는다.

1천만·2천만·3천만 코스튬 18종은 각 투명 5×5 시트에 서기·왼발·오른발·공격 준비·공격과 다섯 방향을 담는다. 걷기는 작성된 한 프레임만 표시하며 다리를 덧그리지 않는다. 같은 배율로 머리 크기를 유지하고 해당 코스튬은 대시의 중복 캐릭터 잔상도 표시하지 않는다.

`skill-looks.mjs`는 가격·소유·직업별 장착을 관리하고 `skill-look-effects.mjs`는 이미 존재하는 전투 이벤트를 그린다. 전투 데미지, 범위, 타수, 회복량, 판정, 쿨타임을 수정하지 않는다. 기본 공격과 적 공격도 유지한다. 1~5차 개인/협동 전투, 사제 보호막, 간략 전투, 아레나 효과를 연결했다. 협동 화면의 기존 개인 이펙트 표시 정책을 따른다. 해제하면 기존 아트가 사용된다.

기존 계정은 첫 명령에서 비어 있는 소유·장착 필드를 초기화한다. 서버의 기존 요청 영수증과 저장 경로를 사용하며 스키마 변경은 필요 없다. 운영 함수는 기존 인증·세션 처리를 보존하고 새로운 엔진/아레나 모듈로만 연결한다.

검증: `skill-looks.test.mjs`에서 18종의 정확한 골드 차감, 중복·잔액·미소유·타직업·전투중 차단, 직업 전환 및 저장 복원, 기본 대비 동일한 능력치, 18개 60초 전투 재생과 아레나 결과 동등성, 1~5차 프레임 배정 및 파일 존재를 확인한다. 기존 배포 워크플로 29개 검사 통과. 실제 앱의 구매·장착·해제·재접속을 로컬 합성 계정으로 확인했다. 브라우저에서 90/90 스킬, 270/270 이미지 프레임, 실제 전투 렌더러의 6직업 1~5차 교체 30/30을 확인했다.

별도 오래된 통합 테스트의 `STARS_REQUIRED` 기대와 아레나 상대 목록 문구 기대는 변경 전 코드에서도 현재 동작과 맞지 않는다. 해당 기존 테스트나 게임 규칙은 이 작업에서 변경하지 않았다.
